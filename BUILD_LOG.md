## Skill / Agent / MCP mechanism decision

The `gather-references` Skill and `reference-gatherer` subagent built for the Assessment 2 exercise (see that entry below) are **not** wired into the live app. This is a deliberate swap, not an oversight, and here's the reasoning: that Skill/agent loop pattern (perceive → reason → act → observe, repeated until a stopping condition) is built for open-ended tasks where the number of steps isn't known up front — "search the web until you've found enough good references." The app's actual AI needs turned out to be different in kind: describing one uploaded image, synthesizing one project's documentation from its entries, and finding one image's focal point are all single-shot content-generation calls with a well-defined input and output — there's nothing to loop over or decide when to stop. Wrapping those in an agent loop would add real complexity (loop control, stopping conditions, multi-step state) with no matching benefit. So the MVP uses direct Gemini API calls (`web/lib/describe.ts`, `web/lib/documentation.ts`, `web/lib/subject-crop.ts`) instead, and the Assessment 2 Skill/agent stands as a separate, working proof of that mechanism against this app's real data (`reference-candidates/emotion-spiral.md`), rather than a component of the product itself.
