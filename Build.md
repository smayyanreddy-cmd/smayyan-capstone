## 2026-09-17

- Pivoted the capstone idea. Replaced the Car Modification Visualiser concept with a new project: the **Creative Continuity Agent** — a tool that ingests scattered creative material (sketches, AI-render experiments, references) with near-zero friction, clusters it by visual + conceptual similarity, tracks how a concept evolves over time, and resurfaces related past work when it's actually useful.
- No code carries over from the old plan; this is effectively a fresh start on a new direction. `Plan.md` has been rewritten in full to describe the new problem statement, MVP scope, user flow, architecture sketch, and open questions.
- Wedge chosen to keep v1 narrow: track the evolution of a single ongoing project that's actively being documented (proof case: personal SR project + automotive fusion sketches), rather than building a general-purpose creative tool.
- MVP scope defined: ingestion (upload + auto-tag), context capture (optional phrase + AI-written description), clustering (image embeddings + LLM conceptual similarity), an evolution timeline view, and contextual resurfacing of 2-3 relevant past pieces triggered by activity.
- Sketched architecture: single web interface for capture + viewing, S3 for image storage, Postgres for metadata, CLIP-style embeddings for visual similarity, Claude for descriptions/tagging/resurfacing explanations.
- Explicitly out of scope for v1: general notebook/moodboard features, multi-user/team collaboration, scheduled notifications.
- Next up: validate the concept before building anything — manually gather existing SR + automotive material into a test set and prototype clustering only (no upload pipeline yet) to see if it surfaces something non-obvious about the existing work.
- Built the clustering validation prototype (`prototype/cluster.py`): given a folder of images, it computes CLIP embeddings (`clip-ViT-B-32` via `sentence-transformers`), groups them with agglomerative clustering on cosine distance, and orders each cluster by file timestamp to approximate an evolution timeline. Optional `--captions captions.json` (filename -> one-line phrase) plus `--describe` calls Claude to write a short combined description per item (needs `ANTHROPIC_API_KEY`). Outputs a readable console summary and `prototype/clusters.json`.
- Verified with `py -3` (Python 3.13, via the `py` launcher — no bare `python`/`pip` on this machine) that the script compiles; full dependency install (`pip install -r prototype/requirements.txt`, notably `sentence-transformers`/torch) not yet run since it's a large download and there's no test image set in the repo yet.
- Next up: gather the SR + automotive test set into a folder, run `py -3 -m pip install -r prototype/requirements.txt` then `py -3 prototype/cluster.py --input <folder>`, and eyeball whether the clusters/timeline surface anything non-obvious before writing any ingestion pipeline.
- Added `.env` support: `.gitignore` (so `.env` never gets committed), an `.env.example` template, a local `.env` with an empty `ANTHROPIC_API_KEY` placeholder to fill in, and `python-dotenv` wired into `prototype/cluster.py` so the key loads automatically when set — only needed for the optional `--describe` step, not plain clustering.
- Ran the first real validation pass: installed `prototype/requirements.txt` and ran the clustering script against a 24-image test set ("Emotion Spiral", WhatsApp exports spanning 2026-08-28 to 2026-09-12).
- Caught and fixed a real bug in the process: `file_timestamp()` was using file mtime, which reflects when the files were downloaded/copied (all showed as today), not when each piece was actually made — the "evolution timeline" was meaningless. Fixed by parsing the real capture date/time out of the WhatsApp export filename pattern (`WhatsApp Image YYYY-MM-DD at H.MM.SS AM/PM`), falling back to mtime only when a filename doesn't match.
- Result on the fixed run: CLIP (default `--threshold 0.35`) split the 24 images into 3 clusters — one large cluster of 18 items spanning almost the whole date range, one singleton (the earliest image, 08-28), and one 5-item cluster mixing dates from 09-04 and 09-12.
- Confirmed with the project owner that all 24 images are actually the same single ongoing project ("Emotion Spiral") — so the 3-way split at default threshold was a false fragmentation, not a real signal. Re-ran at `--threshold 0.5`: all 24 collapsed into one cluster, correctly keeping the project together across the full 08-28 to 09-12 date range. Takeaway: pure CLIP visual similarity alone can wrongly split a single evolving concept at tighter thresholds — it doesn't know about conceptual/character continuity, only pixel-level similarity — so the LLM conceptual layer from the plan matters, not just embeddings.
- Next real test: with the project correctly kept as one cluster, the interesting question is the **evolution view** — does the timestamp-ordered sequence read as a visible progression, and do AI-written descriptions (`--describe`, needs `ANTHROPIC_API_KEY` in `.env`) capture that progression usefully. Not yet run.
